本教學從一個剛安裝好的 GPROXY 開始：新增上游供應商、測試憑證、設定模型名稱，最後用 curl 發出請求。範例使用 OpenAI 相容服務，需要先準備好該服務的 API Key，以及一個它支援的模型 ID。

<VideoTutorial locale="zh-TW" />

## 事前準備

依照[下載與安裝](/zh-tw/download#setup)安裝並啟動 GPROXY，然後進入控制台：

- Application：完成首次設定精靈後，進入應用程式內的控制台。
- CLI：第一次在終端機執行 `gproxy` 時，會在終端機裡進入同樣的精靈。
- 容器：在瀏覽器開啟 `http://127.0.0.1:8787/console/`，以首次啟動時建立的管理員帳戶登入。

如果已經在精靈中建立了供應商和憑證，可以直接跳到第 3 步。

## 1. 新增供應商

進入 **供應商**，新增一個供應商：

- 名稱填寫 `openai-main`。
- 使用 OpenAI 官方服務時，選擇 `openai` 渠道。
- 使用其他 OpenAI 相容服務時，選擇 `custom`，填寫服務位址，並選擇該服務支援的協定，例如 Chat Completions（`openai_chat`）。實際的值請以上游文件為準。

供應商名稱同時也是直接呼叫該供應商時位址的一部分。同一種渠道可以建立多個供應商，各自儲存位址和憑證。

## 2. 新增憑證並測試

開啟該供應商的 **憑證** 分頁，新增上游 API Key。Codex、Claude Code 等需要帳戶登入的渠道會提供登入方式，依照頁面提示完成授權即可。

在憑證上執行 **測試生成**，選擇上游支援的模型，傳送一則簡短訊息。記下測試成功的模型 ID，第 3 步會用到。

<Note>
生成測試會實際呼叫上游，上游可能因此計費。
</Note>

上游 API Key 只會儲存在 GPROXY 中。用戶端呼叫 GPROXY 時使用的是 GPROXY 簽發的閘道 API Key，不會接觸到上游金鑰。

## 3. 建立模型路由

進入 **模型路由**，新增名為 `fast` 的路由，並加入一個成員：供應商選 `openai-main`，上游模型填入第 2 步測試成功的模型 ID。層級和權重保留預設值。

之後用戶端填寫 `fast` 即可。日後要更換上游，只需修改路由成員，不必更動用戶端。不建立路由也可以直接呼叫供應商，見[模型與路由](/zh-tw/guides/models)。

## 4. 傳送請求

傳送請求需要一把閘道 API Key。可以使用首次設定時儲存的金鑰，也可以在控制台 **個人** 檢視的 **我的金鑰** 中新增一把。把下面的預留值換成你的金鑰；如果改過預設連接埠，位址也要跟著修改：

```sh
export GPROXY_KEY='your-gproxy-api-key'
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"你好，请简单介绍自己。"}]}'
```

回傳的是 OpenAI Chat Completions 格式的 JSON，模型的回覆在 `choices` 中。

在 OpenAI 用戶端中設定時，Base URL 填 `http://127.0.0.1:8787/v1`；如果用戶端要求填寫完整的請求 URL，則填範例中的 `/v1/chat/completions` 位址。

其他協定和串流呼叫見[傳送第一個請求](/zh-tw/getting-started/first-request)。Codex CLI、Claude Code 的設定見[CLI 用戶端](/zh-tw/guides/cli-clients)。

## 5. 查看用量

在控制台開啟 **用量** 或 **最近請求**，就能看到剛才那次請求的模型、供應商、token 數和費用。

費用依 GPROXY 中設定的價格規則計算，並非取自上游帳單。上游沒有回報的用量欄位會顯示為空白。

## 常見問題

- 無法連線：確認 GPROXY 正在執行，位址和連接埠正確。
- `401`：請求沒有帶上有效的 GPROXY 閘道金鑰。在這裡填入上游 API Key 一樣會被拒絕。
- `403`：目前的使用者或金鑰沒有使用目標模型的權限。
- `404 unknown_model`：確認 `fast` 路由存在、已啟用，並且已加入成員。
- `429`：觸發了本地限流或費用預算，或上游額度已用完，或暫時沒有可用的憑證。
- 上游回報錯誤或不支援該操作：檢查憑證測試結果、模型 ID、供應商選擇的協定和端點設定。

本教學中的操作也可以透過管理 API 完成，範例見[供應商](/zh-tw/guides/providers)和[模型與路由](/zh-tw/guides/models)。
