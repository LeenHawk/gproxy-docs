本頁介紹 GPROXY 為流量和管理操作保存的各類記錄、如何開啟本文記錄，以及如何透過 API 查詢這些記錄。

<VideoTutorial topic="logs" locale="zh-TW" title="用量與日誌影片教學" />

GPROXY 保存四類記錄，分別回答不同的問題，控制台也會分開顯示：

- 用量記錄：每次上游呼叫消耗了多少、花了多少錢。
- 下游日誌：用戶端向閘道傳送了什麼。
- 上游日誌：閘道實際向哪些上游發出了呼叫。
- 稽核記錄：誰修改了設定。

管理員在 **用量與日誌** 底下查看前三類（**全域用量**、**下游日誌**、**上游日誌**），在 **存取控制 → 稽核** 中查看稽核記錄。每位使用者都可以在 **個人** 檢視的 **用量** 和 **最近請求** 中查看自己的記錄。

## 用量與費用

一筆用量記錄對應一次實際的上游呼叫。用戶端請求發生重試，或切換到其他憑證時，會產生多筆記錄。每筆記錄保存所屬的供應商和憑證、token 數、媒體與工具數量以及費用。用量記錄與請求日誌分開儲存，關閉日誌或封包擷取並不會刪除用量記錄。

上游沒有回報的 token 欄位為 `null`，與 0 不同。`completeness` 表示這筆記錄的用量完整到什麼程度，`metrics` 保存其餘的動態維度和協定細節。

費用依 GPROXY 中設定的價格規則計算，並非讀取上游帳戶餘額。價格缺漏會影響費用統計和預算消耗，見[價格與分層](/zh-tw/reference/pricing)。

**全域設定** 中有兩個相關開關：**儲存用量記錄** 決定是否寫入用量記錄，**結算費用與額度** 決定是否計算費用並計入預算。關閉結算後，就不再檢查預算。

用量彙總可以依時間、模型、供應商、憑證等條件篩選。每次的結果都帶有 `scanned`（掃描的記錄數）和 `truncated`（是否達到掃描上限）。被截斷的結果不是完整帳單，請縮小篩選範圍後重新查詢。

## 請求日誌

下游日誌記錄用戶端到閘道的請求。上游日誌記錄閘道實際發出的呼叫，因此一個下游請求可以關聯多次上游嘗試。

封包擷取會保存選定請求的請求、回應或串流事件，實際保存哪些內容取決於下文的本文記錄設定。

HTTP、SSE 和 WebSocket 流量都會記錄。WebSocket 連線上的每一個訊框都是該連線中的一個事件，訊框數並不等於模型呼叫次數。

## 記錄本文

日誌在 **全域設定** 中設定，上游和下游各有開關：**記錄下游請求**、**記錄下游請求體**、**記錄上游請求**、**記錄上游請求體**。透過 API 設定：

```sh
curl -sS -X PATCH http://127.0.0.1:8787/admin/api/settings \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"logging":{"enableUpstreamLogBody":true}}'
```

記錄本文會占用儲存空間和處理時間。每筆日誌都會標明內容是未擷取、已截斷還是完整；沒有本文並不代表請求沒有送出。封包擷取與用量結算互不影響，關閉封包擷取不會停止結算。

### 日誌遮蔽

預設情況下，辨識出的金鑰、Cookie 和權杖欄位在寫入日誌前會被遮蔽。遮蔽不會辨識本文中的個人資訊或業務資訊。**關閉日誌遮蔽**（`disableLogRedaction`）會完全停用遮蔽，只應在日誌本身受到相應保護時使用。

## 保留期限

**全域設定** 中的以下選項用於清理舊記錄：

- **請求歷史保留天數**：刪除超過該天數的已結束請求記錄與封包擷取，不會刪除用量記錄。
- **用量保留天數**：刪除超過該天數的用量記錄。用量統計和總金額都由用量記錄計算，留空則永久保留。
- **擷取本文保留天數** 與 **擷取本文大小上限（MiB）**：限制保存的封包擷取本文。
- **SQLite 資料庫大小上限（MiB）**：超出上限時，從最舊的已結束請求記錄開始刪除，不會刪除用量記錄。

## 查詢 API

CLI 與容器部署透過 HTTP 提供以下管理介面：

| 路徑 | 內容 |
| --- | --- |
| `/admin/api/usage` | 用量彙總、分組與趨勢 |
| `/admin/api/usage/records` | 逐次上游呼叫的用量記錄 |
| `/admin/api/logs/downstream` | 下游請求清單 |
| `/admin/api/logs/upstream` | 上游呼叫清單 |
| `/admin/api/logs/downstream/{id}` | 下游請求詳細資訊 |
| `/admin/api/logs/captures/{id}` | 封包擷取詳細資訊 |
| `/admin/api/audit` | 稽核記錄 |

每個介面都會檢查呼叫方的管理範圍與能力。個人介面 `/portal/api/usage`、`/portal/api/quota` 和 `/portal/api/requests` 只回傳呼叫方有權查看的資料。

Application 不在 HTTP 連接埠開放這些介面，它的控制台透過應用程式內的 IPC 查詢同樣的資料。

## 稽核

稽核記錄涵蓋管理操作和 OAuth 操作，每筆記錄包括操作者、動作、結果和時間。

設定 `GPROXY_AUDIT_ENABLED=false` 後，就不再寫入新的稽核記錄，既有記錄仍可查詢。這項設定不影響請求日誌和用量結算。

## 處理程序日誌

CLI 把處理程序日誌寫到標準錯誤輸出。`GPROXY_LOG_FILTER` 設定日誌等級，`GPROXY_LOG_FORMAT` 設定格式。

首次啟動時產生的管理員憑據會寫到標準輸出。服務管理程式和容器執行環境通常會把兩路輸出收集到同一份日誌裡，請妥善保管首次啟動的日誌。

預算依用量記錄扣抵，詳見[權限、限流與費用預算](/zh-tw/guides/permissions)。
