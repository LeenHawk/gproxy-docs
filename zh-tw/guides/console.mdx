控制台是 GPROXY 的 Web 介面，個人使用和管理都在這裡完成。本頁介紹控制台各部分的功能，以及範圍管理員如何使用它。

CLI 和容器版本在 `/console` 提供控制台。使用部署時設定的帳號登入；控制台透過 `/portal/api/login` 登入，工作階段儲存在 HttpOnly Cookie 中。

## 首次啟動

CLI 和容器執行個體在首次啟動時建立管理員，在瀏覽器中開啟 `/console/` 用該帳號登入即可，不會顯示設定精靈。

全新的 Application 執行個體則會在進入應用內控制台之前顯示設定精靈，步驟依次為“執行個體設定”“管理員帳戶”“上游渠道”；登入後，在“新增憑據”中為剛建立的供應商新增憑證。詳細步驟見[下載與安裝](/zh-tw/download#setup)。

## 語言

控制台提供英語、簡體中文、繁體中文和俄語（Русский）介面。首次使用時，控制台從瀏覽器或系統設定中選擇一種支援的語言；`ru-RU` 等俄語地區標籤統一使用俄文介面。手動選擇的語言優先，並儲存在當前裝置上。數字和日期按所選語言格式顯示，金額仍使用設定的計費幣種。

## 管理範圍

控制台把 `/portal/api/context` 提供的個人頁面，與 `/admin/api/context` 回傳的管理功能合在一起。能看到哪些內容取決於角色：

- 執行個體管理員管理整個閘道。
- 組織和團隊管理員透過同一個“供應商”入口管理自己範圍內的憑證。他們的“組織”“團隊”頁面只顯示有權存取的物件及其費用預算，不能增刪改身份，也不能修改供應商設定。

如果你管理多個組織或團隊，在帳戶選單中選擇管理範圍。之後的管理請求會在 `x-gproxy-admin-scope` 標頭中攜帶後端提供的範圍標識。切換範圍會關閉正在開啟的編輯視窗和登入流程，並替換該範圍的快取資料；正在提交的寫入需要完成後才能切換。個人頁面不受管理範圍影響。

個人費用預算在“總覽”中與用量一起唯讀顯示，沒有單獨的個人配額頁。預算由管理員在對應的使用者、API Key、組織或團隊上設定。

## 頁面

設定相關頁面及其選單名稱：

| 控制台路徑 | 選單名稱 | 內容 |
| --- | --- | --- |
| `/console/providers` | 供應商 | 供應商設定、憑證、模型、協定轉換、重寫規則繫結、端點覆蓋 |
| `/console/model-routes` | 模型路由 | 跨供應商路由、成員、權重、回退層級和對外模型名 |
| `/console/rule-sets` | 規則集 | 重寫規則、排序以及整組儲存 |
| `/console/model-catalog` | 模型 | 全域模型目錄和全域價格 |
| `/console/settings` | 全域設定 | 執行個體與日誌設定 |
| `/console/settings/transfer` | 設定匯入匯出（“全域設定”中的標籤） | 設定匯出與匯入；`/console/transfer` 開啟同一面板 |
| `/console/clients` | HTTP 用戶端設定 | 可重複使用的連線設定 |
| `/console/tokenizer` | 詞表管理 | 詞表下載和模型詞表繫結 |
| `/console/update` | 系統更新 | 當前宿主支援的更新操作 |

供應商頁面有“憑證”“模型”“規則”“路由規則”“設定”幾個標籤。“路由規則”管理該供應商的操作與協定轉換；“模型路由”負責在多個上游供應商之間選擇。兩者分別設定。

設定表格支援勾選當前頁的記錄並批次刪除；帶啟用開關的記錄還可以批次啟用和停用。修改篩選條件、翻頁或切換管理範圍都會清空已選記錄。每次批次操作都透過現有的交易性設定 API 完成。

## 憑證與上游登入

供應商的憑證在其“憑證”標籤中管理，在這裡新建的憑證和發起的登入流程都歸屬該供應商。可選的歸屬物件限於當前管理範圍。租戶目錄只顯示供應商名稱和可用操作，不顯示閘道設定。

編輯憑證會開啟一個面板，包含“基本設定”“本機限額”“上游額度”三個標籤。在憑證行上也可以直接開啟“上游額度”、測試或刪除憑證。

- 檢視和重新整理密鑰的按鈕在“基本設定”的密鑰欄位下方。
- 修改狀態和“重設健康狀態”在狀態區域。
- 測試對話框會讀取可用模型，並分別顯示結果、耗時和回覆。“測試生成”會真實請求上游。
- 上游額度以金額、次數和重設時間顯示。

### 登入上游

“登入新增憑證”會列出該渠道支援的登入方式。

瀏覽器授權的步驟：

1. 點選“開始登入”，開啟授權連結。
2. 在上游完成授權。
3. 複製包含 `code` 和 `state` 的完整回呼 URL，貼上到控制台中。如果回呼地址是已註冊的本機地址，瀏覽器中的頁面可能打不開，此時照樣從位址列複製回呼地址即可。控制台不會啟動本機回呼監聽服務。
4. 點選“完成登入”。

裝置碼方式：開啟驗證連結，輸入控制台顯示的驗證碼。控制台按後端回傳的間隔輪詢，在成功、拒絕、過期或關閉視窗後停止。

登入工作階段繫結發起登入的使用者、管理範圍和憑證歸屬。完成後只回傳憑證 ID，不回傳密鑰。關閉未完成的流程只會停止介面操作，後端快取的工作階段會自行過期。重新整理頁面不會恢復登入精靈。

上游登入介面都是 `/admin/api/credential-login` 下的 POST 請求：`/authcode/start`、`/authcode/complete`、`/device/start` 和 `/device/poll`，沿用憑證管理的範圍檢查。按憑證發現和測試模型分別使用 `/admin/api/credentials/{id}/models/discover` 和 `/models/test`。

## 配額與價格

### 金鑰預算

管理員在“個人 → 我的金鑰”和“存取控制 → 使用者金鑰”中新建金鑰時，可以在名稱下方直接勾選“設定此密鑰的費用預算”，填寫金額和週期。金鑰與初始預算在同一交易中儲存，預算驗證失敗時不會建立金鑰。編輯已有金鑰會開啟一個面板，包含“基本設定”和“費用預算”兩個標籤。

普通使用者照常自助建立和管理自己的金鑰，費用預算只能由管理員設定。

### 費用預算

使用者、API Key、組織和團隊上都有“費用預算”入口，規則的新增和編輯都在該面板內完成，不再彈出第二層視窗。費用以 USD 十進位字串表示。供應商和憑證上的請求次數限額使用 `count` 單位。

### 預設憑證限額

供應商的“設定 → 預設憑證限額”中的每條規則分別作用於每個憑證，而不是整個供應商共享的預算。這裡只顯示設定，實際用量和重設時間在各個憑證中檢視。

憑證上已啟用的同名規則會覆蓋供應商預設規則。“恢復繼承”會刪除憑證上的這條單獨設定。停用單獨設定同樣會讓已啟用的預設規則重新生效，並不表示取消限額。

憑證限額卡片顯示規則來源、上限、實際用量和下次重設時間。組織和團隊管理員可以檢視生效的限額，由執行個體管理員設定。週期、金額或次數、模型匹配和啟用狀態都可以直接在卡片上修改；自訂時長和固定週期的起點在進階選項中。

### 重設限額

重設供應商預設規則會影響當前繼承它的所有憑證，確認提示會寫明影響範圍。繼承來的卡片沒有單獨的重設按鈕。重設憑證單獨規則或呼叫方預算時，只重設那一條規則。以上操作都不會重設上游帳號的額度。

### 價格

全域價格在“模型”頁編輯，供應商專屬價格在供應商的“模型”標籤中編輯。模型對話框同時管理價格規則、按維度區分的費率以及上下文檔位和服務檔位。

價格規則可以作用於全部供應商或某一個供應商，模型匹配支援 `*` 和 `?`。同一個模型可以有多條按操作區分的規則。價格的計算方式見[價格與分層](/zh-tw/reference/pricing)。

## 匯入匯出

匯入匯出文件包含閘道設定，不包含身份、用量和請求日誌。

- “匯出設定”預設不含憑證密鑰，勾選“包含已儲存的憑證密鑰”後才會匯出，匯出的是已儲存的加密格式。
- “匯入設定”接受當前的 v4 文件格式。選擇檔案後顯示的摘要列出格式版本和記錄數量，這不是後端預檢的結果。

匯入模式決定已有記錄如何處理：

- “合併”更新 ID 相同的記錄，保留檔案中未提及的記錄。
- “取代設定”還會刪除檔案中未提及的記錄，範圍限於可匯出的設定類別。

來自另一個主密鑰的加密密鑰，需要在“來源主密鑰（選填，Hex 或 Base64）”中填寫來源執行個體的主密鑰，後端才能重新加密。不填寫時，目標執行個體必須使用相同的主密鑰。提交後介面會清空該欄位。

匯入在一個交易中完成，提交後宿主會重新載入執行階段設定。請檢視回傳的警告和跳過數量。如果重新載入失敗，結果會顯示設定已經匯入，並附帶一條執行階段警告；資料庫寫入並沒有回滾。

## 字型

CLI 和 Application 版本的控制台預設使用系統字型。可以在應用首次設定時，或之後在設定中的“介面字型”處點選“下載介面字型”，下載 Noto Sans、Noto Sans SC/TC 和 Noto Sans Mono。GPROXY 會依序嘗試從公開的 npm CDN（npmmirror、jsDelivr、unpkg）下載約 9.2 MiB 字型。每個檔案都以自己的 SHA-256 命名，雜湊不符就不接受，因此不需要信任 CDN。字型儲存在本機資料目錄中，離線也能使用。在選擇下載之前，不會發出任何字型請求。點選“刪除字型並使用系統字型”即可恢復系統字型。

Edge 部署把字型作為同源靜態資源提供。headless 套件既不含控制台，也不含字型。

v4.1.14 及更早的版本從 `https://gproxy.leenhawk.com/fonts/` 下載字型，文件站已不再提供這些檔案，所以在這些版本上下載會失敗，控制台繼續使用系統字型。升級後即可恢復。

## 構建控制台

依次執行 `pnpm --dir console lint`、`pnpm --dir console test` 和 `pnpm --dir console build`。構建會做型別檢查、用 Vite 打包，並把資源複製到控制台的嵌入目錄。之後構建的原生程式會在 `/console` 提供這些資源；Edge 部署則把同一份資源作為閘道前的靜態資源提供。見[構建](/zh-tw/development/building)。
