GPROXY 為 Cloudflare Workers、Netlify Functions 和 Vercel Functions 提供部署範本，適合不想自行維護伺服器的情境。Docker、Render 和 Heroku 請參閱 [Docker、Render 與 Heroku](/zh-tw/deployment/containers)。

範本在建置時下載預先編譯的發行套件，不需要 Rust 工具鏈。控制台和 API 使用部署的同一個網域，控制台入口為 `/console/`。

## 選擇平台

| 平台 | 平台資料庫 | 既有資料庫 | WebSocket / Realtime |
| --- | --- | --- | --- |
| [Cloudflare Workers](#cloudflare-workers) | 部署時建立 D1 | libSQL / Turso | 支援 |
| [Netlify Functions](#netlify) | Netlify Database | PostgreSQL | 不支援 |
| [Vercel Functions](#vercel) | 部署時選擇 PostgreSQL 產品 | PostgreSQL | 支援（平台 Beta） |

三個平台都支援 HTTP 和 SSE 串流呼叫。用戶端需要 WebSocket 或 Realtime 時，請選擇 Cloudflare Workers 或 Vercel，或者改用 [CLI 或容器部署](/zh-tw/download)。

在 Cloudflare 上，閘道以 WebAssembly 形式在 Worker 中執行；在 Netlify 和 Vercel 上，由一個小型 Node.js 函式啟動原生 `gproxy-serverless` 程式，並將請求轉送給它。三者的管理 API 和控制台相同，資料庫類型、函式時長和請求大小限制則由平台決定。

## 部署前的準備

每個範本都要求填寫兩項金鑰，請先準備好並妥善保存：

- `GPROXY_ADMIN_PASSWORD`：控制台登入密碼，至少 8 個字元。
- `GPROXY_MASTER_KEY`：32 位元組主金鑰，用於加密資料庫中的上游憑證，寫成 64 位十六進位或 base64。可以用 `openssl rand -hex 32` 產生。

使用者名稱預設為 `admin`，也可以另外設定 `GPROXY_ADMIN_USER`。密碼在每次啟動時生效：存在同名使用者時，只修改該使用者的密碼；沒有同名使用者時，重新啟用 0 號管理員，並改為設定的使用者名稱和密碼。完整規則請參閱設定參考中的[首次初始化](/zh-tw/reference/configuration#首次初始化)。

<Warning>
每次更新和重新部署都要使用同一個 `GPROXY_MASTER_KEY`。以一把金鑰加密的憑證無法用另一把金鑰解開，一旦更換金鑰，資料庫中所有上游憑證都將無法讀取。
</Warning>

如果連線既有資料庫而非平台資料庫，還要準備好連線資訊。各平台需要填寫哪些值，請參閱下文對應小節。

## Cloudflare Workers

[![Deploy to Cloudflare](https://deploy.workers.cloudflare.com/button)][cloudflare-auto]

[使用外部 libSQL / Turso 資料庫][cloudflare-external]

部署按鈕會建立 D1 資料庫。第二個連結部署的版本會連線既有的 libSQL 或 Turso 資料庫，不建立 D1。

1. 開啟所選入口，連結 GitHub 或 GitLab 帳戶。
2. 使用 D1 時填寫資料庫名稱，Cloudflare 會建立資料庫並以 `DB` 繫結。使用外部資料庫時，填寫 `GPROXY_DATABASE_URL` 和 `GPROXY_LIBSQL_TOKEN`。
3. 填寫管理員密碼和主金鑰。建置指令保持 `npm run build`，部署指令保持 `npm run deploy`，然後開始部署。

Turso 位址可以寫成 `libsql://your-db.turso.io`，也可以寫成對應的 HTTPS 位址。Worker 透過 libSQL 的 HTTP 介面存取資料庫，因此不能填寫 PostgreSQL 連線字串。

使用 D1 的部署之後也可以透過這兩個變數改用 libSQL，`GPROXY_DATABASE_URL` 優先於 D1 繫結。切換連線只是換一個資料庫，D1 中的資料不會被複製過去。

需要自行用 Wrangler 部署或修改 Worker 設定時，請參閱[手動部署到 Cloudflare](#手動部署到-cloudflare)。

## Netlify

[![Deploy to Netlify](https://www.netlify.com/img/deploy/button.svg)][netlify-auto]

[使用既有 PostgreSQL 資料庫][netlify-external]

部署按鈕使用 Netlify Database。第二個連結開啟同一個範本，並多出一個填寫外部 PostgreSQL 連線的欄位。

1. 開啟所選入口，授權儲存庫，填寫管理員密碼和主金鑰。
2. 使用 Netlify Database 時，函式讀取平台提供的連線字串，無需填寫。使用既有資料庫時，將 PostgreSQL 連線字串填入 `GPROXY_DATABASE_URL`。
3. 保留範本的建置指令和 Functions 設定，開始部署。

外部連線字串形如 `postgresql://user:password@db.example.com/gproxy?sslmode=require`，請依資料庫服務商提供的資訊填寫。

即使填寫了外部連線，Netlify 仍可能建立平台資料庫。這不影響使用，因為程式優先讀取 `GPROXY_DATABASE_URL`。

## Vercel

[![Deploy with Vercel](https://vercel.com/button)][vercel-auto]

[使用既有 PostgreSQL 資料庫][vercel-external]

部署按鈕會要求關聯一個新的 PostgreSQL 產品；第二個連結略過這一步，改為要求填寫 `GPROXY_DATABASE_URL`。

1. 開啟所選入口。使用部署按鈕時，依提示選擇並關聯 PostgreSQL 產品。
2. 填寫管理員密碼和主金鑰；使用既有資料庫時，再填寫 `GPROXY_DATABASE_URL`。
3. 保留範本的建置指令和 `vercel.json`，開始部署。

函式依序從 `GPROXY_DATABASE_URL`、`DATABASE_URL`、`POSTGRES_URL` 讀取連線字串。如果所關聯的產品使用其他變數名稱，請將它的值複製到 `GPROXY_DATABASE_URL`。

範本使用 Node.js Functions，不要改成 Edge Runtime：函式需要啟動一個原生程式，Edge Runtime 做不到。

## 登入

1. 開啟 `https://你的網域/console/`。直接造訪網域也會進入控制台。
2. 以 `admin`（或 `GPROXY_ADMIN_USER` 中設定的使用者名稱）和設定的密碼登入。
3. 新增供應商和憑證，並測試憑證。
4. 建立模型路由和 API key，然後依[第一個請求](/zh-tw/getting-started/first-request)發出呼叫。

用戶端以部署位址作為服務位址，例如 `https://gateway.example.com/v1`，並使用剛建立的 API key 驗證。

在 Netlify 和 Vercel 上，如果閘道無法啟動，請求會得到 503 狀態碼和訊息 `GPROXY is unavailable. Check the deployment database and secrets in the platform console.`。此時請查看函式日誌，常見原因有：沒有關聯資料庫，連線字串不是以 `postgres://` 或 `postgresql://` 開頭，或者沒有設定密碼或主金鑰。程式必須在 45 秒內回報就緒，資料庫連不上時通常表現為啟動逾時。PostgreSQL 帳戶還需要有建立 `gproxy` schema 和應用程式資料表的權限。

## 更新

設定、帳戶和用量都儲存在資料庫中，更新只替換程式。請保留資料庫和主金鑰。

D1 範本以及 Netlify、Vercel 範本在建置時下載最新穩定版，並依發行版本中的 `SHA256SUMS` 驗證 SHA-256。升級時清除平台建置快取並重新部署即可。需要固定版本時，將建置環境變數 `GPROXY_RELEASE_VERSION` 設為發行標籤，該版本必須包含對應平台的發行套件。

外部資料庫版的 Cloudflare 範本與此不同：它的 `prepare-release.mjs` 寫死了一個發行標籤（目前為 `v4.2.0`），不讀取 `GPROXY_RELEASE_VERSION`。升級時請在部署所建立的儲存庫中修改這個檔案裡的標籤，再重新部署。

託管部署不使用控制台的原地二進位更新。

## 執行限制

所有範本都支援 HTTP 和 SSE。Netlify Functions 不接受 WebSocket 升級，閘道會以 501 狀態碼拒絕這類請求。Vercel 透過平台的 [WebSocket Beta](https://vercel.com/docs/functions/websockets) 支援 WebSocket。無論哪個平台，函式時長限制和執行個體回收都可能中斷 WebSocket，用戶端需要自行重新連線。

Vercel 範本在 `vercel.json` 中將 `maxDuration` 設為 300 秒。長時間推理、大型檔案和高並行仍受各平台限制，部署前請對照 [Netlify Functions](https://docs.netlify.com/build/functions/overview/) 和 [Vercel Functions](https://vercel.com/docs/functions/limitations) 的目前額度評估。

Netlify 和 Vercel 範本不設定檔案儲存。需要 S3、R2 或可透過公開連結下載的檔案時，請依下文自行建置 Worker，或改用 CLI 部署。

OAuth 端點和檔案發布連結需要知道閘道的公開位址。在 Netlify 和 Vercel 上，可以用 `GPROXY_PUBLIC_BASE_URL` 固定這個位址；不設定時，函式使用平台回報的正式環境位址。如果無從得知公開位址，OAuth 端點依每個請求本身的 `Host` 回應，發布連結保持停用。Workers 上則在 `GPROXY_CONFIG` 中設定 `public_base_url`（見下文）。

## 手動部署到 Cloudflare

### 使用發行套件

從發行頁面下載 `gproxy-edge-cloudflare.zip`，解壓縮後進入其中的 `cloudflare` 目錄。套件內有建置好的 Worker、控制台和 `wrangler.toml`。

使用 D1 時，安裝相依套件並建立資料庫：

```sh
pnpm install
pnpm exec wrangler d1 create gproxy
```

將 Wrangler 輸出的資料庫 ID 填入 `wrangler.toml`，binding 名稱保持為 `DB`：

```toml
[[d1_databases]]
binding = "DB"
database_name = "gproxy"
database_id = "replace-with-your-database-id"
```

將主金鑰和管理員密碼存為 Secrets，先預檢再部署：

```sh
pnpm exec wrangler secret put GPROXY_MASTER_KEY
pnpm exec wrangler secret put GPROXY_ADMIN_PASSWORD
pnpm exec wrangler deploy --dry-run
pnpm exec wrangler deploy
```

改用 libSQL 時，設定 `GPROXY_DATABASE_URL` 和 `GPROXY_LIBSQL_TOKEN`，並刪除不用的 D1 binding。發行套件建置時已啟用 libSQL 支援，自行建置時要保留這個 feature。

GPROXY 在首次啟動時自動建立資料表，不需要執行 Wrangler SQL migrations。

### Worker 設定

`GPROXY_CONFIG` 存放 JSON 格式的設定檔，`GPROXY_MASTER_KEY` 等具名 Secrets 會覆寫其中對應的欄位。下面的範例使用 D1，並設定公開位址：

```toml
[vars]
GPROXY_CONFIG = '{"store":{"kind":"d1","binding":"DB"},"cache":{"kind":"store"},"public_base_url":"https://gateway.example.workers.dev"}'
```

控制台由 Workers Assets 提供，載入控制台不會執行 Worker。請保留範本中的路由設定，讓 `/console/` 走靜態資源，其餘路徑進入閘道：

```toml
[assets]
directory = "./public"
binding = "ASSETS"
not_found_handling = "single-page-application"
run_worker_first = ["/*", "!/", "!/console", "!/console/*"]
```

Worker 可以使用 D1 或 libSQL，沒有本機 SQLite、TCP 資料庫連線和本機檔案目錄。需要 S3 或 R2 檔案儲存時，建置時啟用 `s3` feature，設定 `GPROXY_S3_ACCESS_KEY_ID` 和 `GPROXY_S3_SECRET_ACCESS_KEY`，並在設定中加入檔案儲存欄位。欄位說明請參閱[設定參考](/zh-tw/reference/configuration)。

### 從原始碼建置

在儲存庫根目錄執行：

```sh
rustup target add wasm32-unknown-unknown
cargo install worker-build
pnpm --dir console install --frozen-lockfile
pnpm --dir deploy/cloudflare install
pnpm --dir deploy/cloudflare build
pnpm --dir deploy/cloudflare check
```

`build` 將 Worker 編譯到 `deploy/cloudflare/build/`，將控制台放到 `deploy/cloudflare/public/`；`check` 是 Wrangler 的預檢部署。其他建置與打包選項請參閱[從原始碼建置](/zh-tw/development/building)。
