This tutorial takes a freshly installed GPROXY to a working request: you add an upstream provider, test a credential, give it a model name and call it with curl. It uses an OpenAI-compatible service, so you need an API key for that service and a model ID it supports.

<VideoTutorial locale="en" />

## Before you start

Install and start GPROXY as described in [Download and install](/download#setup), then open the console:

- Application: complete the setup wizard; it opens the in-app console.
- CLI: the first time `gproxy` runs in a terminal, it runs the same wizard there.
- Container: open `http://127.0.0.1:8787/console/` and sign in with the administrator account created on first startup.

If the wizard already created a provider and credential for you, skip to step 3.

## 1. Add a provider

Open **Providers** and create a new provider:

- Name it `openai-main`.
- For the official OpenAI service, select the `openai` channel.
- For another OpenAI-compatible service, select `custom`, enter the service's base URL and select the protocols it supports, for example Chat Completions (`openai_chat`). The upstream's documentation tells you which.

The provider name is also part of the URL for calling this provider directly. You can create several providers on the same channel, each with its own address and credentials.

## 2. Add and test a credential

Open the provider's **Credentials** tab and add the upstream API key. Channels that sign in with an account, such as Codex or Claude Code, offer a login option instead; follow its authorization steps.

Run **Test generation** on the credential, pick a model the upstream supports and send a short message. Note the model ID that worked; step 3 needs it.

<Note>
Generation tests are real upstream requests and may be charged by the upstream.
</Note>

The upstream key stays in GPROXY. Clients call GPROXY with a gateway API key that GPROXY issues, and never see the upstream key.

## 3. Create a model route

Open **Model routes**, create a route named `fast` and add one member: provider `openai-main`, upstream model the ID you tested in step 2. Leave the tier and weight at their defaults.

Clients can now ask for `fast`. To move them to another upstream later, you edit the route member and leave the clients alone. A provider can also be called without any route; see [Models and routes](/guides/models).

## 4. Send a request

You need a gateway API key. Use the one saved during setup, or create one under **Your keys** in the console's **Personal** view. Put it in place of the placeholder below, and change the port if you changed it from the default:

```sh
export GPROXY_KEY='your-gproxy-api-key'
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"Hello. Please introduce yourself briefly."}]}'
```

The response is an OpenAI Chat Completions JSON object with the model's reply in `choices`.

To configure an OpenAI client, set its Base URL to `http://127.0.0.1:8787/v1`. If the client asks for the complete request URL instead, give it the `/v1/chat/completions` address from the example.

[First request](/getting-started/first-request) shows the same call in the other protocols and with streaming. [CLI clients](/guides/cli-clients) covers Codex CLI and Claude Code.

## 5. Check usage

Open **Usage** or **Recent requests** in the console. The record shows the model, provider, token counts and cost of the request you just sent.

The cost is computed from the pricing rules configured in GPROXY, not taken from the upstream bill. Usage fields the upstream did not report stay empty.

## Troubleshooting

- Cannot connect: check that GPROXY is running and that the address and port are correct.
- `401`: the request did not carry a valid GPROXY gateway key. An upstream API key is rejected here.
- `403`: the user or key is not permitted to use the target model.
- `404 unknown_model`: check that the `fast` route exists, is enabled and has a member.
- `429`: a local rate limit or budget was reached, the upstream allowance is used up, or no credential is currently available.
- Upstream error or unsupported operation: check the credential test result, the model ID, the provider's protocol selection and its endpoint configuration.

Everything in this tutorial can also be done through the management API; [Providers](/guides/providers) and [Models and routes](/guides/models) have the API examples.
