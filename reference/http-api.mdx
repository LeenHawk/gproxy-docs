---
title: "HTTP API Reference"
description: "Complete request, response and event schemas for forwarding, management, portal and OAuth APIs."
---

This reference describes every HTTP endpoint with its parameters, request
body, responses and the data structures they use. It is generated from the
Rust wire types, the management DTOs and the host's route declarations, and
request and response schemas follow their Serde definitions. Each endpoint has
its own page under **HTTP API** in the sidebar, grouped into Forwarding,
Codex provider, Management, Portal, OAuth and System.

Shared forwarding paths choose the protocol from the request headers, and
`stream: true` selects the streaming operation. SSE schemas describe one
decoded event; WebSocket schemas describe the messages exchanged after the
upgrade. Binary and multipart payloads keep their own content types.

Forwarding paths also work under a provider or namespace prefix, and the
Codex-specific paths require the name of a Codex provider. For mounts,
authentication and management scopes, see
[Routing & Endpoints](/reference/routing-table).

The complete specification is available as [OpenAPI JSON](/generated/openapi.json),
which you can import into Postman, Insomnia or a code generator.
