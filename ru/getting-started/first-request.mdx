На этой странице показано, как вызывать GPROXY по каждому поддерживаемому протоколу, с потоковой передачей и без неё, и что означают типичные коды ошибок. Предполагается, что вы прошли [Быстрый старт](/ru/getting-started/quick-start) и у вас есть маршрут модели `fast` и API-ключ шлюза. В примерах используется адрес по умолчанию `http://127.0.0.1:8787`; если вы меняли порт, исправьте его.

```sh
export GPROXY_KEY='your-gproxy-api-key'
```

## Передача ключа

GPROXY читает ключ шлюза из заголовка `Authorization: Bearer <key>`, `x-api-key` или `x-goog-api-key`, поэтому подходит заголовок, привычный для каждого протокола. Если в запросе их несколько, первым используется `Authorization`, затем `x-api-key`, затем `x-goog-api-key`. CLI и контейнер также принимают параметр запроса Gemini `?key=`; заголовок всегда имеет приоритет над ним.

Здесь всегда передаётся ключ шлюза. Учётные данные вышестоящих сервисов хранятся в провайдерах, и шлюз их не принимает.

## OpenAI Chat Completions

```sh
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"Say hello."}]}'
```

## OpenAI Responses

```sh
curl -sS http://127.0.0.1:8787/v1/responses \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","input":"Say hello."}'
```

## Claude Messages

```sh
curl -sS http://127.0.0.1:8787/v1/messages \
  -H "x-api-key: $GPROXY_KEY" \
  -H 'anthropic-version: 2026-10-21' \
  -H 'content-type: application/json' \
  -d '{"model":"fast","max_tokens":256,
       "messages":[{"role":"user","content":"Say hello."}]}'
```

## Gemini GenerateContent

В Gemini имя модели указывается в пути, а не в теле запроса:

```sh
curl -sS "http://127.0.0.1:8787/v1beta/models/fast:generateContent" \
  -H "x-goog-api-key: $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"contents":[{"parts":[{"text":"Say hello."}]}]}'
```

## Потоковая передача

Для OpenAI и Claude укажите в теле `"stream":true`. Передайте curl флаг `-N`, чтобы он выводил события по мере поступления, а не буферизовал их:

```sh
curl -sSN http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","stream":true,
       "messages":[{"role":"user","content":"Count to three."}]}'
```

В Gemini для этого есть отдельный метод `streamGenerateContent`, а `alt=sse` включает server-sent events:

```sh
curl -sSN "http://127.0.0.1:8787/v1beta/models/fast:streamGenerateContent?alt=sse" \
  -H "x-goog-api-key: $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"contents":[{"parts":[{"text":"Count to three."}]}]}'
```

## Какой протокол выбрать

Маршрут `fast` работает со всеми примерами выше, по какому бы протоколу ни работал его вышестоящий сервис. GPROXY отвечает по протоколу, на котором пришёл запрос клиента, и в промежутке преобразует данные в формат вышестоящего сервиса и обратно.

Преобразование не добавляет возможностей. Успех запроса по-прежнему зависит от участников маршрута, от того, что поддерживает вышестоящий сервис, и от того, поддерживается ли конкретное преобразование. Функция, которой нет у вышестоящего сервиса, остаётся недоступной и при вызове через другой эндпоинт.

## Список моделей

Каталог моделей в консоли показывает настроенные имена моделей шлюза. Чтобы получить через API каталог, видимый вызывающему:

```sh
curl -sS http://127.0.0.1:8787/portal/api/models \
  -H "Authorization: Bearer $GPROXY_KEY"
```

У каждой записи есть поле `permitted`, которое показывает, может ли вызывающий её использовать. Приложение не обслуживает `/portal/api` по HTTP; в нём пользуйтесь каталогом внутри приложения.

`GET /v1/models` работает иначе: он передаёт список моделей выбранного вышестоящего сервиса, а не каталог шлюза.

## Выбор провайдера или пространства имён

Цель определяется префиксом URL вместе с именем модели:

| URL | Модель в запросе | Цель |
| --- | --- | --- |
| `/v1/chat/completions` | `fast` | Маршрут `fast` |
| `/openai-main/v1/chat/completions` | Идентификатор модели у вышестоящего сервиса | Провайдер `openai-main` |
| `/acme/v1/chat/completions` | `fast` | Маршрут `acme/fast` |

Правила именования приведены в разделе [Модели и маршруты](/ru/guides/models).

## Типичные ошибки

| Код | Значение |
| --- | --- |
| `400` | Некорректный запрос или значение конфигурации |
| `401` | Ключ отсутствует, недействителен, отключён или истёк |
| `403` | Недостаточно прав или области OAuth |
| `404` | Неизвестная модель, маршрут или ресурс |
| `429` | Сработал лимит запросов или квота |
| `5xx` | Сбой шлюза или вышестоящего сервиса; смотрите журналы |

Каждый запрос появляется в консоли в записях об использовании и о запросах. Сохраняются ли тела запросов и ответов, зависит от настроек журналирования; см. [Использование, журналы и аудит](/ru/guides/observability).
