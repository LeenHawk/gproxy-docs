Это руководство проводит только что установленный GPROXY до первого работающего запроса: вы добавите вышестоящего провайдера, проверите учётные данные, назначите им имя модели и вызовете её через curl. В примере используется OpenAI-совместимый сервис, поэтому понадобятся API-ключ этого сервиса и идентификатор поддерживаемой им модели.

## Подготовка

Установите и запустите GPROXY, как описано в разделе [Загрузка и установка](/ru/download#setup), затем откройте консоль:

- Приложение: пройдите мастер настройки, после него откроется встроенная консоль.
- CLI: при первом запуске `gproxy` в терминале тот же мастер запускается прямо в терминале.
- Контейнер: откройте `http://127.0.0.1:8787/console/` и войдите под учётной записью администратора, созданной при первом запуске.

Если мастер уже создал провайдера и учётные данные, переходите к шагу 3.

## 1. Добавьте провайдера

Откройте **Провайдеры** и создайте нового провайдера:

- Назовите его `openai-main`.
- Для официального сервиса OpenAI выберите канал `openai`.
- Для другого OpenAI-совместимого сервиса выберите `custom`, укажите базовый URL сервиса и отметьте поддерживаемые им протоколы, например Chat Completions (`openai_chat`). Какие протоколы поддерживаются, написано в документации вышестоящего сервиса.

Имя провайдера также входит в URL для прямого обращения к этому провайдеру. На одном канале можно создать несколько провайдеров, у каждого свой адрес и свои учётные данные.

## 2. Добавьте и проверьте учётные данные

Откройте вкладку **Учётные данные** провайдера и добавьте API-ключ вышестоящего сервиса. Каналы, которые входят через учётную запись, например Codex или Claude Code, вместо этого предлагают вход; выполните шаги авторизации.

Запустите **Проверить генерацию** для учётных данных, выберите модель, которую поддерживает вышестоящий сервис, и отправьте короткое сообщение. Запомните идентификатор модели, с которым проверка прошла: он понадобится на шаге 3.

<Note>
Проверка генерации отправляет настоящие запросы вышестоящему сервису, и он может выставить за них счёт.
</Note>

Ключ вышестоящего сервиса остаётся в GPROXY. Клиенты обращаются к GPROXY с API-ключом шлюза, который выдаёт GPROXY, и ключ вышестоящего сервиса не видят.

## 3. Создайте маршрут модели

Откройте **Маршруты моделей**, создайте маршрут с именем `fast` и добавьте одного участника: провайдер `openai-main`, модель вышестоящего сервиса — идентификатор, проверенный на шаге 2. Уровень и вес оставьте по умолчанию.

Теперь клиенты могут запрашивать `fast`. Чтобы позже перевести их на другой вышестоящий сервис, достаточно изменить участника маршрута, клиентов менять не нужно. К провайдеру можно обращаться и без маршрута; см. [Модели и маршруты](/ru/guides/models).

## 4. Отправьте запрос

Понадобится API-ключ шлюза. Используйте ключ, сохранённый при настройке, или создайте новый в разделе **Ваши ключи** в представлении **Личный кабинет** консоли. Подставьте его вместо заполнителя ниже и измените порт, если вы меняли его со значения по умолчанию:

```sh
export GPROXY_KEY='your-gproxy-api-key'
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"Hello. Please introduce yourself briefly."}]}'
```

В ответ приходит JSON-объект OpenAI Chat Completions, ответ модели находится в `choices`.

Чтобы настроить клиент OpenAI, укажите в качестве Base URL `http://127.0.0.1:8787/v1`. Если клиент требует полный URL запроса, укажите адрес `/v1/chat/completions` из примера.

В разделе [Первый запрос](/ru/getting-started/first-request) тот же вызов показан для других протоколов и с потоковой передачей. Настройка Codex CLI и Claude Code описана в разделе [CLI-клиенты](/ru/guides/cli-clients).

## 5. Проверьте использование

Откройте в консоли **Использование** или **Последние запросы**. В записи указаны модель, провайдер, количество токенов и стоимость только что отправленного запроса.

Стоимость вычисляется по правилам цен, настроенным в GPROXY, а не берётся из счёта вышестоящего сервиса. Поля использования, которые вышестоящий сервис не сообщил, остаются пустыми.

## Устранение неполадок

- Не удаётся подключиться: проверьте, что GPROXY запущен, а адрес и порт указаны верно.
- `401`: в запросе нет действительного API-ключа шлюза GPROXY. Ключ вышестоящего сервиса здесь отклоняется.
- `403`: пользователю или ключу не разрешено использовать целевую модель.
- `404 unknown_model`: проверьте, что маршрут `fast` существует, включён и имеет участника.
- `429`: достигнут локальный лимит запросов или бюджет, исчерпана квота вышестоящего сервиса или сейчас нет доступных учётных данных.
- Ошибка вышестоящего сервиса или неподдерживаемая операция: проверьте результат проверки учётных данных, идентификатор модели, выбранные протоколы провайдера и настройку его эндпоинтов.

Всё, что сделано в этом руководстве, можно выполнить и через API управления; примеры API приведены в разделах [Провайдеры](/ru/guides/providers) и [Модели и маршруты](/ru/guides/models).
