本页介绍使用 GPROXY 的账户，以及调用模型所用的网关 API Key：首个管理员、用户、组织与团队，以及密钥的创建、传递、轮换和撤销。

<VideoTutorial topic="users" locale="zh-CN" title="用户与密钥视频教程" />

GPROXY 有两种身份凭据。登录控制台用用户名和密码，客户端调用模型用网关 API Key。上游凭证属于供应商，只用于访问上游，不能用来登录 GPROXY。

## 首个管理员

Application 在首次设置向导中创建管理员。

CLI 在空实例上启动时会创建管理员，并显示生成的密码和 API Key。如果想自己指定，在首次启动前设置以下变量：

```sh
export GPROXY_ADMIN_USER='admin'
export GPROXY_ADMIN_PASSWORD='your-initial-password'
export GPROXY_BOOTSTRAP_ADMIN_API_KEY='your-initial-gateway-key'
./gproxy serve
```

新实例上密码和密钥变量都可以省略，省略的值由程序生成。`GPROXY_BOOTSTRAP_ADMIN_API_KEY` 只在首次初始化时读取。

<Warning>
`GPROXY_ADMIN_PASSWORD` 在每次启动时都会生效，不限于首次。存在名为 `GPROXY_ADMIN_USER` 的用户时，把该用户的密码设为此值；没有同名用户时，恢复内置的 0 号管理员：改为该名称、重新启用并设为 `admin` 角色、设置此密码，同时结束其现有的控制台会话。不再需要时请删除这个变量，否则在控制台改过的密码会在重启后被覆盖。
</Warning>

供应商需要在控制台中添加。旧的 `GPROXY_BOOTSTRAP_CHANNELS` 变量已不再创建供应商。

CLI 与容器部署的登录入口是 `/console/`。个人页面和管理页面共用一个登录会话，保存在名为 `gproxy_session` 的 HTTP Cookie 中，有效期由 `session_ttl_secs` 配置。Application 使用应用内控制台。

## 用户、组织与团队

实例管理员在 **成员与组织 → 用户** 中创建用户。用户角色为 `admin` 或 `user`。没有设置密码的用户不能登录控制台，但仍可在权限范围内使用签发给自己的 API Key。

组织和团队通过成员关系把用户分组，每条成员关系带有该用户在组内的角色。组织管理员和团队管理员只能管理本范围内开放的功能，并不是实例管理员。各范围能管理的内容见[控制台与范围管理](/zh-cn/guides/console)。

API Key 可以绑定一个组织或团队。绑定决定密钥能使用哪些共享凭证，以及计入哪些组的费用预算。绑定关系保存在密钥上，客户端无法通过发送组织或团队请求头来改变。

## 创建密钥

用户在控制台 **个人** 视图的 **我的密钥** 中管理自己的密钥。实例管理员可以在 **访问控制 → 用户密钥** 中管理所有用户的密钥。

密钥包含以下设置：

- **名称**：用于区分使用该密钥的应用或设备。
- 归属：所属用户，以及可选绑定的组织或团队。
- **过期时间** 与 **启用**：过期或停用的密钥不能发起新请求。
- **管理权限**：允许密钥调用管理 API，但仍受所属用户和范围的权限约束。默认关闭，由管理员在 **用户密钥** 中设置。
- **留存密钥原文**：保存完整密钥，以便以后再次查看。默认关闭，只能在创建时选择。
- **费用预算**：管理员可以为密钥设置金额、周期和模型范围。

创建后页面会显示完整密钥，请立即复制。未留存原文的密钥无法再次显示，从其他实例仅以摘要导入的密钥也是如此。查看已留存的密钥同样需要相应权限。

新密钥和初始预算一起保存。预算校验失败时，密钥也不会创建。

## 传递密钥

```text
Authorization: Bearer <gateway-key>
x-api-key: <gateway-key>
x-goog-api-key: <gateway-key>
```

使用客户端协议惯用的请求头，并且只传一把密钥。同时存在多个时，依次优先读取 `Authorization`、`x-api-key`、`x-goog-api-key`。

调用管理 API 需要启用了管理权限的密钥。普通推理密钥不会因为所属用户是管理员而自动获得管理权限。

## 轮换与撤销

轮换会替换密钥的值，旧值立即失效，所有使用它的客户端都要更新配置。如果想逐个迁移客户端，可以改为新建第二把密钥，客户端全部切换后再停用或删除旧密钥。

管理 API 中的对应操作：

- `POST /admin/api/api-keys/{id}/rotate`：轮换。
- `GET /admin/api/api-keys/{id}/secret`：查看已保留的密钥。
- 个人 API 使用 `/portal/api/keys/{id}/rotate` 和 `/portal/api/keys/{id}/secret`。

撤销在执行写入的实例上立即生效。多实例部署中，其他实例根据内存快照应答认证，重新加载后才拒绝该密钥：通常经共享缓存的失效通知在毫秒级完成；通知丢失时，最迟在 30 秒一次的修订号轮询后完成。参见[架构](/zh-cn/development/architecture)。

把成员移出组织或团队时，会在同一事务中停用该用户绑定到该组织或团队的密钥，包括 OAuth 内部密钥。

## OAuth 会话

GPROXY 可以作为 OAuth 授权服务器：客户端请求用户授权，然后取得访问令牌。每次授权背后都有一把内部密钥。内部密钥不同于普通用户密钥，不能手动创建、不能显示，也不能当作 Bearer Key 使用。

用户可以在 **账号 → 已授权的程序** 中查看和撤销已授权的程序。在 **访问控制 → OAuth 客户端** 中注销某个客户端，会撤销它的全部授权和令牌。

客户端配置和授权流程见[CLI 客户端](/zh-cn/guides/cli-clients)。OAuth 令牌可以使用哪些 scope 和操作，见[权限、限流与费用预算](/zh-cn/guides/permissions#oauth-访问令牌)。
