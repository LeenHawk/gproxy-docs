GPROXY 保存四类记录，分别回答不同的问题，控制台也分开显示：

- 用量记录：每次上游调用消耗了多少、花了多少钱。
- 下游日志：客户端向网关发送了什么。
- 上游日志：网关实际向哪些上游发起了调用。
- 审计记录：谁修改了配置。

管理员在 **用量与日志** 下查看前三类（**全局用量**、**下游日志**、**上游日志**），在 **访问控制 → 审计** 中查看审计记录。每个用户都可以在 **个人** 视图的 **用量** 和 **最近请求** 中查看自己的记录。

## 用量与费用

一条用量记录对应一次实际的上游调用。客户端请求发生重试，或切换到其他凭证时，会产生多条记录。每条记录保存归属的供应商和凭证、token 数、媒体与工具数量以及费用。用量记录与请求日志分开保存，关闭日志或抓包不会删除用量记录。

上游没有报告的 token 字段为 `null`，与 0 不同。`completeness` 表示这条记录的用量完整到什么程度，`metrics` 保存其余的动态维度和协议细节。

费用按 GPROXY 中配置的价格规则计算，并非读取上游账户余额。价格缺失会影响费用统计和预算消耗，见[价格与分层](/zh-cn/reference/pricing)。

**全局设置** 中有两个相关开关：**保存用量记录** 决定是否写入用量记录，**结算费用与额度** 决定是否计算费用并计入预算。关闭结算后，不再检查预算。

用量汇总可以按时间、模型、供应商、凭证等条件筛选。每次结果都带有 `scanned`（扫描的记录数）和 `truncated`（是否触及扫描上限）。被截断的结果不是完整账单，请缩小筛选范围后重新查询。

## 请求日志

下游日志记录客户端到网关的请求。上游日志记录网关实际发出的调用，因此一个下游请求可以关联多次上游尝试。

抓包保存选定请求的请求、响应或流事件，具体保存哪些取决于下文的正文记录设置。

HTTP、SSE 和 WebSocket 流量都会记录。WebSocket 连接上的每一帧都是连接中的一个事件，帧数并不等于模型调用次数。

## 记录正文

日志在 **全局设置** 中配置，上游和下游分别有开关：**记录下游请求**、**记录下游请求体**、**记录上游请求**、**记录上游请求体**。通过 API 设置：

```sh
curl -sS -X PATCH http://127.0.0.1:8787/admin/api/settings \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"logging":{"enableUpstreamLogBody":true}}'
```

记录正文会占用存储空间和处理时间。每条日志都会标明内容是未捕获、已截断还是完整的；没有正文并不代表请求没有发出。抓包与用量结算互不影响，关闭抓包不会停止结算。

### 脱敏

默认情况下，识别出的密钥、Cookie 和令牌字段在写入日志前会被遮蔽。脱敏不会识别正文中的个人信息或业务信息。**关闭日志脱敏**（`disableLogRedaction`）会完全停用遮蔽，只应在日志本身受到相应保护时使用。

## 保留期限

**全局设置** 中的以下选项用于清理旧记录：

- **请求历史保留天数**：删除超过该天数的已结束请求记录与抓包，不删除用量记录。
- **用量保留天数**：删除超过该天数的用量记录。用量统计和总金额都由用量记录计算，留空则永久保留。
- **捕获正文保留天数** 与 **捕获正文大小上限（MiB）**：限制保存的抓包正文。
- **SQLite 数据库大小上限（MiB）**：超出上限时，从最旧的已结束请求记录开始删除，不删除用量记录。

## 查询 API

CLI 与容器部署通过 HTTP 提供以下管理接口：

| 路径 | 内容 |
| --- | --- |
| `/admin/api/usage` | 用量汇总、分组与趋势 |
| `/admin/api/usage/records` | 逐次上游调用的用量记录 |
| `/admin/api/logs/downstream` | 下游请求列表 |
| `/admin/api/logs/upstream` | 上游调用列表 |
| `/admin/api/logs/downstream/{id}` | 下游请求详情 |
| `/admin/api/logs/captures/{id}` | 抓包详情 |
| `/admin/api/audit` | 审计记录 |

每个接口都会检查调用方的管理范围与能力。个人接口 `/portal/api/usage`、`/portal/api/quota` 和 `/portal/api/requests` 只返回调用方有权查看的数据。

Application 不在 HTTP 端口开放这些接口，其控制台通过应用内 IPC 查询同样的数据。

## 审计

审计记录涵盖管理操作和 OAuth 操作，每条记录包括操作者、动作、结果和时间。

设置 `GPROXY_AUDIT_ENABLED=false` 后不再写入新的审计记录，已有记录仍可查询。这个设置不影响请求日志和用量结算。

## 进程日志

CLI 把进程日志写到标准错误。`GPROXY_LOG_FILTER` 设置日志级别，`GPROXY_LOG_FORMAT` 设置格式。

首次启动时生成的管理员凭据写到标准输出。服务管理器和容器运行时通常会把两路输出收集到同一份日志里，请妥善保管首次启动的日志。

预算根据用量记录扣减，详见[权限、限流与费用预算](/zh-cn/guides/permissions)。
