完整的网关需要一个进程和一个数据库，因此只能原生运行或在容器中运行。serverless 平台运行的是 `gproxy-lite`：一个独立的轻量引擎，使用同样的渠道和同样的协议转换，编译为一个 WebAssembly 模块，每个平台配一层很薄的 JavaScript 外壳。

## 有什么，没有什么

`gproxy-lite` 只服务一个运维者。它有：

- 完整网关的全部渠道，包括通过 OAuth 登录的渠道；
- HTTP 上的全部操作，支持所有方言：内容生成（流式或非流式）、token 计数、嵌入、图像、模型列表、压缩、文件和视频。上游使用客户端的方言时直接透传，否则先转换；
- Cloudflare 上的 WebSocket 操作，转发给支持 WebSocket 的上游。

它没有：

- 用户、组织、团队、API Key 和权限：一把访问密钥放行所有请求；
- 预算、配额、计价、用量记录、限流和审计记录；
- 每个供应商多把凭证、凭证选择，以及换另一把凭证重试；
- 路由、别名和层级：请求要指明供应商；
- 重写规则和按操作设置的路由规则：路由方式是渠道的默认值；
- 控制台、管理 API 和多实例同步；
- MCP 服务器和渠道服务路由（用量页面、配额查询）；
- 本地模型目录和 tokenizer：上游不支持的操作会被拒绝，不做估算；
- 文件存储：经过转换的图像请求不能返回 URL，只能返回 `b64_json`；
- 把 Responses WebSocket 客户端转换到 HTTP 上游。

需要其中任何一项时，请使用[容器](/zh-cn/deployment/containers)部署。

## 配置

全部配置是环境变量 `GPROXY_LITE_CONFIG` 中的一个 JSON 文档。其中有访问密钥和上游凭证，请作为机密保存。

```json
{
  "access_key": "what clients send as their API key",
  "providers": [
    { "name": "openai", "channel": "openai", "credential": "sk-..." },
    {
      "name": "local",
      "channel": "custom",
      "base_url": "https://llm.example.com",
      "config": { "dialects": ["openai_chat"] },
      "credential": "upstream-key"
    },
    {
      "name": "vertex",
      "channel": "vertex",
      "credential": { "kind": "service_account", "secret": { "type": "service_account" } }
    },
    { "name": "codex", "channel": "codex" }
  ]
}
```

| 字段 | 含义 |
| --- | --- |
| `access_key` | 客户端出示的密钥：作为 bearer token，或放在 `x-api-key`、`x-goog-api-key`、`?key=` 中。 |
| `providers[].name` | 字母、数字、`.`、`_` 和 `-`。它是路径前缀，也是模型前缀。`lite` 为保留名。 |
| `providers[].channel` | 渠道 id，见[渠道目录](/zh-cn/reference/channel-catalog)。 |
| `providers[].base_url`、`config` | 渠道自己的设置，与完整网关中供应商的设置相同。 |
| `providers[].credential` | 粘贴的 API Key 写成字符串；渠道自有格式的密钥写成 `{ "kind", "secret" }`。需要登录的渠道不填。 |

引擎无法使用的配置（未知渠道、名称重复、渠道不接受的凭证）在启动时被拒绝，此后每个请求都返回 `500` 并说明原因。

## 指定供应商

- `/{provider}/v1/...` 发往该供应商。模型名是上游自己的名称。
- 不带前缀时，模型字段写成 `provider/model`。
- 只配置了一个供应商时，前缀可以省略。

配置了多个供应商时，不带前缀的 `GET /v1/models` 列出所有供应商的模型，每个 id 前面加上供应商名。

```sh
curl https://your-deployment.example/v1/chat/completions \
  -H "Authorization: Bearer $ACCESS_KEY" -H "Content-Type: application/json" \
  -d '{"model":"openai/gpt-5.5","messages":[{"role":"user","content":"Hi"}]}'
```

## 登录 OAuth 渠道

没有 `credential` 的供应商通过三个路径登录，这些路径都需要访问密钥。浏览器重定向不需要到达部署本身。

<Steps>
  <Step title="开始">
    ```sh
    curl -X POST https://your-deployment.example/lite/login/start \
      -H "Authorization: Bearer $ACCESS_KEY" -H "Content-Type: application/json" \
      -d '{"provider":"codex"}'
    ```

    响应中有一个 `session`，另有一个要在浏览器中打开的 `authorize_url`；设备码登录时则是 `user_code` 和 `verification_uri`。两种流程都支持的渠道可以传 `"mode": "authorization_code"` 或 `"device_code"`。
  </Step>
  <Step title="授权">
    打开该 URL 并同意授权。授权码登录最后会停在一个打不开的页面（`localhost` 地址），或一个显示授权码的页面：复制完整地址，或复制授权码。
  </Step>
  <Step title="完成">
    ```sh
    curl -X POST https://your-deployment.example/lite/login/complete \
      -H "Authorization: Bearer $ACCESS_KEY" -H "Content-Type: application/json" \
      -d '{"session":"...","callback_url":"http://localhost:1455/auth/callback?code=...&state=..."}'
    ```

    `callback_url` 和 `code` 只发送其中一个。设备码登录只发送 `session`；响应为 `{"status":"pending"}` 时，每隔 `interval_secs` 秒重复一次。`{"status":"ready"}` 表示凭证已保存。
  </Step>
</Steps>

`GET /lite/status` 列出每个供应商及其凭证的状态：`none`、`configured`、`signed_in` 或 `dead`。`dead` 表示上游拒绝续期该凭证，`reason` 是原因，只有重新登录才能替换它。

## 保持登录

会过期的凭证在三种情况下续期：请求发现它即将过期时，上游返回 `401` 时，以及按计划定时续期，这样一段时间没有请求也不会掉登录。每个模板每天运行一次计划，时间是 UTC 04:00。`POST /lite/renew`（需要访问密钥）可以随时手动执行同样的操作，并返回每个可续期供应商的结果：

```json
{
  "renewals": [
    { "provider": "codex", "outcome": "renewed" },
    { "provider": "claude", "outcome": "not_due" },
    { "provider": "kiro", "outcome": "no_credential" },
    { "provider": "gemini", "outcome": "failed", "reason": "..." }
  ]
}
```

只要有一次续期失败，这次运行就会在平台的日志中记为失败。

| 平台 | 由什么运行 | 计划写在哪里 | 限制 |
| --- | --- | --- | --- |
| Cloudflare Workers | Cron Trigger 和 Worker 的 `scheduled` 处理函数 | `wrangler.toml` 中的 `[triggers] crons` | 所有套餐的最小间隔都是一分钟。Free 套餐每个账号最多五个 Cron Trigger。 |
| Netlify | Scheduled Function `renew` | `netlify.toml` 中的 `[functions."renew"] schedule` | 所有套餐可用。只在已发布的部署上运行，每次最多 30 秒，没有 URL。 |
| Vercel | 请求 `GET /lite/renew` 的 Cron Job | `vercel.json` 中的 `crons` | Hobby：每天最多一次，在指定的那一小时内启动；更频繁的表达式会导致部署失败。Pro：最小间隔一分钟。 |

在 Vercel 上，把环境变量 `CRON_SECRET` 设为至少 16 个字符的随机字符串，然后重新部署。Vercel 把它作为定时请求的 Bearer 令牌发送，函数只接受带有它的定时请求。没有 `CRON_SECRET` 时定时请求会被拒绝，不会按计划续期。

每天一次足以保住 refresh token，它的有效期以天计或更长。如果计划没有运行，或者间隔比会话的有效期还长（`playground` 渠道每十分钟轮换一次 Cookie），请求仍然会续期凭证；闲置太久的凭证需要重新登录。

同一个凭证的续期不会重叠，因为有些上游在 refresh token 被使用两次时会吊销这次登录的全部令牌。续期前先取得租约：一个仅在不存在时才创建的存储条目，30 秒后过期。其他实例发现租约已被占用时，最多等待 10 秒，然后使用续期后的凭证。持有者中途退出时，租约到期，下一次续期接手。续期时间超过租约的，仍可能与下一次续期重叠，这时保存哪个结果由比较并交换决定。

## 状态

引擎记住的所有内容都在每个部署的一个键值存储中：登录得到或续期过的凭证、进行中的登录，以及协议转换在请求之间保留的状态。粘贴的凭证留在配置中，只有在渠道为它续期后才写入存储。凭证按上游签发的原样存储，没有完整网关的主密钥加密，请限制谁能读取该存储。

| 平台 | 存储 | 比较并交换 |
| --- | --- | --- |
| Cloudflare Workers | 一个使用 SQLite 存储的 Durable Object | 原子：该对象一次只执行一个调用，其存储是强一致的。 |
| Netlify | Netlify Blobs，以强一致方式读取 | 写入是原子的（`onlyIfMatch`、`onlyIfNew`）。Blobs 没有条件删除，因此删除时写入一个墓碑，键仍然存在；释放的租约就是这样一个墓碑，下一次续期会覆盖它。 |
| Vercel | Marketplace 中的 Upstash Redis | 原子：在单个主节点上执行一个 Lua 脚本。 |

## 部署

[仓库 README](https://github.com/LeenHawk/gproxy#readme) 中的 Cloudflare、Netlify 和 Vercel 按钮部署这些模板，不需要 Rust 工具链。它们的构建步骤 `npm run build` 运行 `prepare-lite.mjs`：从 `staging` 发布（由 `main` 构建）下载 `gproxy-lite.zip`，用该发布的 `SHA256SUMS` 校验后解压到 `lite/`。要使用稳定版，把 `GPROXY_LITE_RELEASE` 设为 `latest` 或某个标签，例如 `v4.3.1`。按钮会要求填写 `GPROXY_LITE_CONFIG`；Vercel 还会添加 Upstash Redis，并要求填写 `CRON_SECRET`。

自己构建模块时，模板位于[仓库](https://github.com/LeenHawk/gproxy)的 `deploy/lite`。`prepare-lite.mjs` 不会覆盖已经存在的 `lite/`。构建需要带 `wasm32-unknown-unknown` 目标的 Rust，以及与 `Cargo.lock` 中版本一致的 `wasm-bindgen-cli`：

```sh
rustup target add wasm32-unknown-unknown
cargo install wasm-bindgen-cli --version 0.2.130
sh deploy/lite/build.sh
```

所有渠道都会编译进模块。模块大小为 10.7 MB，gzip 压缩后 4.0 MB。

<Tabs>
  <Tab title="Cloudflare Workers">
    ```sh
    cd deploy/lite/cloudflare
    wrangler secret put GPROXY_LITE_CONFIG
    wrangler deploy
    ```

    Worker 在 `wrangler.toml` 中声明了它的 Durable Object，不需要事先创建任何资源。本地运行时，把 `dev.vars.example` 复制为 `.dev.vars`，然后启动 `wrangler dev`。
  </Tab>
  <Tab title="Netlify">
    ```sh
    cd deploy/lite/netlify
    npm install
    netlify env:set GPROXY_LITE_CONFIG '{"access_key":"..."}' --secret
    netlify deploy --prod
    ```

    引擎作为 Netlify Function 运行。函数最多运行 60 秒，流式响应也不例外，更长的生成会被截断。WebSocket 请求返回 `501`。
  </Tab>
  <Tab title="Vercel">
    从 Marketplace 为项目添加 Upstash Redis，它会设置 `KV_REST_API_URL` 和 `KV_REST_API_TOKEN`。然后：

    ```sh
    cd deploy/lite/vercel
    vercel env add GPROXY_LITE_CONFIG
    vercel env add CRON_SECRET
    vercel deploy --prod
    ```

    引擎作为 Node.js 函数运行，最长运行时间为 300 秒。WebSocket 请求返回 `501`。
  </Tab>
</Tabs>
