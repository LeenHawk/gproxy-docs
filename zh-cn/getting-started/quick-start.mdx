本教程从一个刚安装好的 GPROXY 开始：添加上游供应商、测试凭证、配置模型名，最后用 curl 发出请求。示例使用 OpenAI 兼容服务，需要准备该服务的 API Key 和一个它支持的模型 ID。

<VideoTutorial locale="zh-CN" />

## 准备工作

按[下载与安装](/zh-cn/download#setup)安装并启动 GPROXY，然后进入控制台：

- Application：完成首次设置向导后进入应用内控制台。
- CLI：首次在终端中运行 `gproxy` 时，会在终端里进入同样的向导。
- 容器：在浏览器打开 `http://127.0.0.1:8787/console/`，用首次启动时创建的管理员账户登录。

如果向导中已经创建了供应商和凭证，可以直接跳到第 3 步。

## 1. 添加供应商

进入 **供应商**，新建一个供应商：

- 名称填写 `openai-main`。
- 使用 OpenAI 官方服务时，选择 `openai` 渠道。
- 使用其他 OpenAI 兼容服务时，选择 `custom`，填写服务地址，并选择该服务支持的协议，例如 Chat Completions（`openai_chat`）。具体取值以上游文档为准。

供应商名称同时是直接调用该供应商时地址的一部分。同一种渠道可以建多个供应商，各自保存地址和凭证。

## 2. 添加凭证并测试

打开该供应商的 **凭证** 标签页，添加上游 API Key。Codex、Claude Code 等需要账户登录的渠道提供登录方式，按页面提示完成授权即可。

在凭证上执行 **测试生成**，选择上游支持的模型，发送一条简短消息。记下测试成功的模型 ID，第 3 步要用。

<Note>
生成测试会真实调用上游，上游可能因此计费。
</Note>

上游 API Key 只保存在 GPROXY 中。客户端调用 GPROXY 时使用 GPROXY 签发的网关 API Key，接触不到上游密钥。

## 3. 创建模型路由

进入 **模型路由**，新建名为 `fast` 的路由，并添加一个成员：供应商选 `openai-main`，上游模型填第 2 步测试成功的模型 ID。层级和权重保留默认值。

此后客户端填写 `fast` 即可。以后要换上游，只需修改路由成员，不必改动客户端。不建路由也可以直接调用供应商，见[模型与路由](/zh-cn/guides/models)。

## 4. 发送请求

发送请求需要一把网关 API Key。可以使用首次设置时保存的密钥，也可以在控制台 **个人** 视图的 **我的密钥** 中新建一把。把下面的占位值替换为你的密钥；如果改过默认端口，地址也要相应修改：

```sh
export GPROXY_KEY='your-gproxy-api-key'
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"你好，请简单介绍自己。"}]}'
```

返回的是 OpenAI Chat Completions 格式的 JSON，模型的回复在 `choices` 中。

在 OpenAI 客户端中配置时，Base URL 填 `http://127.0.0.1:8787/v1`；如果客户端要求填写完整请求 URL，则填示例中的 `/v1/chat/completions` 地址。

其他协议和流式调用见[发送第一个请求](/zh-cn/getting-started/first-request)。Codex CLI、Claude Code 的配置见[CLI 客户端](/zh-cn/guides/cli-clients)。

## 5. 查看用量

在控制台打开 **用量** 或 **最近请求**，可以看到刚才那次请求的模型、供应商、token 数和费用。

费用按 GPROXY 中配置的价格规则计算，并非取自上游账单。上游没有报告的用量字段显示为空。

## 常见问题

- 无法连接：确认 GPROXY 正在运行，地址和端口正确。
- `401`：请求没有带上有效的 GPROXY 网关密钥。在这里填上游 API Key 同样会被拒绝。
- `403`：当前用户或密钥没有使用目标模型的权限。
- `404 unknown_model`：确认 `fast` 路由存在、已启用，并且添加了成员。
- `429`：触发了本地限流或费用预算，或上游额度已用完，或暂时没有可用凭证。
- 上游报错或不支持该操作：检查凭证测试结果、模型 ID、供应商的协议选择和端点配置。

本教程中的操作也可以通过管理 API 完成，示例见[供应商](/zh-cn/guides/providers)和[模型与路由](/zh-cn/guides/models)。
