本页演示如何用各个协议调用 GPROXY（包括流式响应），并列出常见错误码的含义。前提是已经完成[快速开始](/zh-cn/getting-started/quick-start)，有一个名为 `fast` 的模型路由和一把网关 API Key。示例使用默认地址 `http://127.0.0.1:8787`，改过端口时请相应调整。

```sh
export GPROXY_KEY='your-gproxy-api-key'
```

## 传递密钥

GPROXY 从 `Authorization: Bearer <key>`、`x-api-key` 或 `x-goog-api-key` 中读取网关密钥，各协议惯用的请求头都可以使用。同时带有多个时，依次优先使用 `Authorization`、`x-api-key`、`x-goog-api-key`。CLI 与容器部署还接受 Gemini 风格的 `?key=` 查询参数，但请求头始终优先。

这里只能填网关签发的密钥。上游凭证保存在供应商中，网关不接受。

## OpenAI Chat Completions

```sh
curl -sS http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","messages":[{"role":"user","content":"Say hello."}]}'
```

## OpenAI Responses

```sh
curl -sS http://127.0.0.1:8787/v1/responses \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","input":"Say hello."}'
```

## Claude Messages

```sh
curl -sS http://127.0.0.1:8787/v1/messages \
  -H "x-api-key: $GPROXY_KEY" \
  -H 'anthropic-version: 2026-10-21' \
  -H 'content-type: application/json' \
  -d '{"model":"fast","max_tokens":256,
       "messages":[{"role":"user","content":"Say hello."}]}'
```

## Gemini GenerateContent

Gemini 的模型名写在路径中，而不是请求体里：

```sh
curl -sS "http://127.0.0.1:8787/v1beta/models/fast:generateContent" \
  -H "x-goog-api-key: $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"contents":[{"parts":[{"text":"Say hello."}]}]}'
```

## 流式响应

OpenAI 和 Claude 协议在请求体中设置 `"stream":true`。curl 需要加 `-N`，事件到达时立即输出，不做缓冲：

```sh
curl -sSN http://127.0.0.1:8787/v1/chat/completions \
  -H "Authorization: Bearer $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"model":"fast","stream":true,
       "messages":[{"role":"user","content":"Count to three."}]}'
```

Gemini 使用单独的 `streamGenerateContent` 方法，加上 `alt=sse` 以 SSE 格式返回：

```sh
curl -sSN "http://127.0.0.1:8787/v1beta/models/fast:streamGenerateContent?alt=sse" \
  -H "x-goog-api-key: $GPROXY_KEY" \
  -H 'content-type: application/json' \
  -d '{"contents":[{"parts":[{"text":"Count to three."}]}]}'
```

## 协议的选择

上面所有示例都可以调用同一个 `fast` 路由，与上游实际使用的协议无关。GPROXY 按客户端请求的协议返回响应，中间负责与上游格式之间的转换。

转换不会增加功能。请求能否成功，仍取决于路由成员、上游支持的能力，以及这一对协议之间的转换是否受支持。上游没有的功能，换一个端点调用也不会有。

## 模型列表

控制台的模型目录列出已配置的网关模型名。通过 API 查询当前调用方可见的目录：

```sh
curl -sS http://127.0.0.1:8787/portal/api/models \
  -H "Authorization: Bearer $GPROXY_KEY"
```

每个条目的 `permitted` 字段表示当前调用方能否使用。Application 不在 HTTP 端口提供 `/portal/api`，请在应用内查看目录。

`GET /v1/models` 与此不同，它转发的是所选上游的模型列表，而不是网关目录。

## 指定供应商或命名空间

地址前缀和模型名共同决定目标：

| 地址 | 请求中的模型名 | 目标 |
| --- | --- | --- |
| `/v1/chat/completions` | `fast` | 名为 `fast` 的路由 |
| `/openai-main/v1/chat/completions` | 上游模型 ID | `openai-main` 供应商 |
| `/acme/v1/chat/completions` | `fast` | 名为 `acme/fast` 的路由 |

命名规则见[模型与路由](/zh-cn/guides/models)。

## 常见错误

| 状态码 | 含义 |
| --- | --- |
| `400` | 参数格式或配置值无效 |
| `401` | 密钥缺失、无效、停用或过期 |
| `403` | 权限或 OAuth 授权范围不足 |
| `404` | 模型、路由或资源不存在 |
| `429` | 请求受到限流或限额约束 |
| `5xx` | 网关或上游调用失败，需结合日志检查 |

每次请求都会出现在控制台的用量和请求记录中。请求和响应正文是否保存取决于日志设置，详见[用量、日志与审计](/zh-cn/guides/observability)。
